# Практика 3–4: REST API Design и OpenAPI Governance

Добро пожаловать на практический курс! В этом репозитории мы будем проектировать реальный банковский контракт API «Лента истории операций», проходить ревью и автоматизировать проверки.

## 🛠 Подготовка окружения (Выполнить ДО занятия)

Пожалуйста, выполните эти шаги заранее, чтобы на занятии мы сразу перешли к практике.


**Важно:** для корпоративных устройств с ограниченными правами администратора используйте вариант установки через корпоративный каталог ПО. Если политика компании разрешает установку с сайтов разработчиков — используйте этот вариант.

### Шаг 1. Установка VS Code

Установите следующие инструменты **до** клонирования репозитория:
Инструмент     | Вариант А (корпоративный каталог ПО) | Вариант Б (сайты разработчиков)
VS Code	      | Software Center → Visual Studio Code | code.visualstudio.com
Git	         | Software Center → Git	               | git-scm.com
Node.js (LTS)	| Software Center → Node.js LTS	      | nodejs.org
Java JDK 21	   | Software Center → Java JDK 21	      | adoptium.net

При установке VS Code с сайта разработчика на экране «Выберите дополнительные задачи» обязательно поставьте галочки:

   * ✅ Создать значок на Рабочем столе
   * ✅ Добавить действие "Открыть с помощью Code" в контекстное меню
   * ✅ Зарегистрировать Code в качестве редактора
   * ✅ **Добавить в PATH (доступно после перезагрузки)** — это критически важно для работы терминала.
При установке Node.js не забудьте галочку «Add to PATH».

### Шаг 2. Перезагрузка компьютера
**Это обязательный шаг.** Git, Node.js и Java часто не определяются в терминале до перезапуска системы. После установки всего ПО перезагрузите компьютер.

### Шаг 3. Проверка установки
Откройте VS Code. В верхнем меню выберите Терминал → Новый терминал (или нажмите Ctrl+~). Внизу откроется командная строка.
Выполните три команды:
```bash
git --version
node --version
java --version
```
Все три команды должны вернуть версию без ошибок. Если какая-то команда не найдена — проверьте, что инструмент установлен и добавлен в PATH, и при необходимости перезагрузите компьютер ещё раз.

### Шаг 4. Клонирование репозитория

1. Перейдите в папку, где будет храниться проект (например, на Рабочий стол):

```bash
cd Desktop
```

2. Склонируйте репозиторий. На странице GitHub нажмите зелёную кнопку Code и скопируйте ссылку HTTPS (она начинается с https://github.com/...). Вставьте ссылку в терминал:

```bash
git clone <ССЫЛКА_HTTPS>
```

Если при клонировании откроется окно авторизации GitHub — войдите через браузер.

3. Перейдите в созданную папку:

```bash
cd operations-api-practice
```

4. Откройте проект одним из способов:
- В терминале: code .
- Через меню VS Code: Файл → Открыть папку... → выберите папку operations-api-practice.

5. Убедитесь, что открыта именно папка репозитория:
- В заголовке окна VS Code отображается имя папки (operations-api-practice).
- В левой панели Explorer видна структура проекта (api/, docs/, test-openapi.yaml и т.д.).
- В терминале VS Code команда pwd (macOS/Linux) или cd (Windows) показывает путь к папке репозитория.

Если появится окно «Вы доверяете авторам файлов в этой папке?» — нажмите «Да, я доверяю».

### Шаг 5. Установка расширений VS Code
- На левой панели VS Code нажмите на иконку Extensions (квадратики) или нажмите Ctrl+Shift+X.
- В строке поиска введите OpenAPI (Swagger) Editor.
- Внимание: выберите плагин именно от разработчика 42Crunch (у него должна быть галочка верификации). Нажмите Install.
- Аналогично установите плагин YAML от разработчика Red Hat.

Функциональная проверка расширения OpenAPI (не ориентируйтесь только на иконку):
- Откройте файл test-openapi.yaml.
- Убедитесь, что YAML подсвечивается (цветовая разметка ключей и значений).
- Нажмите Ctrl+Shift+P (или Cmd+Shift+P на macOS) и введите OpenAPI.
В списке команд должны появиться команды расширения (например, OpenAPI: Validate, OpenAPI: Audit).
- Если команды доступны и файл подсвечивается — расширение работает.

Примечание: зелёная иконка OpenAPI в правом верхнем углу может отсутствовать в зависимости от версии расширения. Ориентируйтесь на функциональную проверку через палитру команд.

### Шаг 6. Установка инструментов проверки контракта (Spectral, swagger-cli, openapi-generator)
В терминале VS Code выполните три команды по очереди (каждая займёт несколько секунд):

```bash
npm install -g @stoplight/spectral-cli
npm install -g @apidevtools/swagger-cli
npm install -g @openapitools/openapi-generator-cli
```

Проверка: введите эти команды, каждая должна показать номер версии:

```bash
spectral --version
swagger-cli --version
openapi-generator-cli version
```

### Шаг 7. Настройка Git
Если вы впервые работаете с Git, укажите ваше имя и email в терминале VS Code (чтобы ваши коммиты были подписаны):

```bash
git config --global user.name "Ваше Имя"
git config --global user.email "ваш-email@example.com"
```

🚀 **Как начать работу на занятии**
Убедитесь, что вы находитесь в папке проекта и терминал VS Code открыт.

Переключитесь на ветку вашей команды:

Группа А (Продуктовый контур):

```bash
git checkout feature/team-a
```

Группа Б (Платформенный контур):

```bash
git checkout feature/team-b
```

📂 **Структура репозитория**
api/openapi.yaml — здесь вы будете писать ваш контракт.

docs/ — сюда вы будете складывать артефакты (глоссарий, REST-таблицу, карту схем и т.д.).

test-openapi.yaml — файл для проверки работы плагинов VS Code.

.spectral.yaml — правила проверки контракта (корпоративный стандарт).


🛠 **Быстрая шпаргалка команд (Терминал VS Code)**
Проверить синтаксис YAML (validate):

```bash
swagger-cli validate api/openapi.yaml
```

(Должно вернуть: api/openapi.yaml is valid)

Проверить стиль и правила (lint):

```bash
spectral lint api/openapi.yaml
```

(Должно вернуть: No results with a severity of 'error' found!)

Сгенерировать Java-код из контракта (codegen):

```bash
openapi-generator-cli generate -i api/openapi.yaml -g java -o generated/java/
```

(Код появится в папке generated/java/)

Сохранить изменения в Git:

```bash
git add .
git commit -m "feat: описание того, что сделали"
git push origin feature/team-a
```

Если при команде git push Git запросит пароль, введите не ваш обычный пароль от GitHub, а Personal Access Token (PAT). Если вы работаете через встроенный терминал VS Code, он обычно сам перехватывает эту команду и открывает окно авторизации в браузере.
