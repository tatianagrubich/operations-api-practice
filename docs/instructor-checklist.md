## 2. Схема темы 3 (подтверждение)

Схема «3.1 → 3.2 → 3.3» подтверждена:

- **3.1:** ресурсная модель из темы 2 → REST-дизайн (URI, методы, параметры, статусы).
- **3.2:** REST-дизайн → OpenAPI schemas → draft `api/openapi.yaml`.
- **3.3:** draft → поиск дефектов → исправленный контракт → quality gate → review.
- **Итог темы 3** — вход в тему 4.

Четыре PDF-задания — часть единого сценария, а не дополнительная самостоятельная работа сверх упражнений в презентации.

## 8. Баланс групп

Обе группы работают с `api/openapi.yaml`, а не только со своими внутренними алгоритмами:

- **Группа 1:** проектирует контракт (OpenAPI, схемы, идемпотентность, пагинация).
- **Группа 2:** в заданиях №3 и №4 дополнительно описывает фрагмент OpenAPI (структуру ответа или стриминг-API).
- **Группа 1** в задании №4 дополнительно уточняет разделение cursor-based и offset-пагинации в контракте.

Таким образом, обе группы отрабатывают ключевые навыки проектирования контракта, а не получают два разных результата обучения.
